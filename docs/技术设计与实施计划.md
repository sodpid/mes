## 1. 现场事实与技术选择

2026-10-20 只读检查：项目只有上述两份设计文档，未发现业务代码或额外 AGENTS.md。Node.js v24.13.0、npm 11.12.1 可用，Docker 服务返回 29.4.3。Python 命令为 WindowsApps 占位路径，未取得有效版本，不作为运行依赖。Node 内置 SQLite 可加载但显示实验性提示，本方案不依赖它。

| 层次 | 选择 | 原因与边界 |
| --- | --- | --- |
| 形态 | 模块化单体，单个后端服务 | 主数据和未来库存业务需要一致事务；当前无需微服务和消息队列 |
| 语言与工程 | TypeScript、npm workspaces | 前后端统一类型语言，本机已有 Node；锁定依赖并提交 lockfile（是否提交 Git 另依授权） |
| API | Fastify、Zod 校验、node-postgres（pg） | 路由、校验、事务边界明确；用参数化 SQL，不引入通用动态表模型 |
| 数据库 | PostgreSQL 17，Docker Compose 本地独立实例 | 外键、唯一约束、事务、NUMERIC 支持后续制造及库存；本机 Docker 已可用 |
| 界面 | React、Vite、Ant Design 中文组件 | 快速形成列表、表单、树形分类和详情，满足业务维护操作；不只提供 API |
| 数值 | decimal.js + PostgreSQL NUMERIC(20,6) | API 十进制用字符串，避免 JS Number 造成换算误差 |
| 验证 | Vitest/API 集成测试，Playwright 浏览器验收 | 重点测业务约束及真实界面操作；独立测试数据库 |

实施时选择与 Node 24 兼容的稳定版本并记录精确 lockfile，不盲用所有包的 latest。初版使用实际 PostgreSQL，禁止为通过测试将真实持久化替换为内存或浏览器 localStorage。Docker 不可用时应报告具体错误并修复环境；若需更换数据库，回到设计阶段评估，不能静默降级。

本地默认端口：前端 5173、API 3001、数据库 54329（容器内 5432），均绑定 127.0.0.1，允许环境变量覆盖。Compose 服务及卷使用项目专属名称，不能清理或占用其他项目数据。开发前端代理 /api 到后端；构建后后端可托管静态文件，同源使用。生产 HTTPS、多人规模、备份目标在生产部署阶段落实。

## 2. 本轮实施切片 S1

本轮由实施代理交付 S1：**可启动、可登录、有中文 UI 和持久化 API 的首批主数据应用**。

包括：公司、工厂、仓库、库位、往来单位（客户/供应商多角色）、计量单位、物料分类、物料、辅助单位换算、工厂供应/生产策略、非工序检验要求配置；基础权限、审计、启停用和引用检查。

不在 S1：车间/工作中心/工序页面、BOM/路线/检验标准版本管理、库存余额和出入库、采购销售生产单据、计划净算、委外单据。它们保留为一期后续 S2～S4，不假装已经完成，不建立一批不能使用的占位业务页面。

对应 U-005、F-001/F-002 的相关部分，并落实 R-008 的组织边界及 F-010/F-014/F-015 所需的物料策略基础。不能将 F-001、F-002 全部或 U-009 标为完成；完整范围仍按基线核验。

建议目录：

```text

  server.ts              # 监听与优雅退出
  modules/auth/          # 登录、会话、角色和组织范围
  modules/master-data/   # 各资料路由、业务服务、SQL 仓储

  api/                   # API 客户端和错误处理
  pages/                 # 中文主数据页面
  components/            # 通用列表、状态、审计和引用展示
packages/shared/src/     # 枚举、请求响应 schema，不能含数据库连接或秘密
```

可以复用列表和表单组件，但业务服务保留显式实体校验；不做任意表名 SQL API。业务保存通过 service → transaction → repository，路由只处理输入、身份及响应。所有 SQL 参数化，表名和排序字段来自代码白名单。

## 4. 数据库模型与约束

### 4.1 通用落地规则

- 主键 UUID，由服务端生成；时间 timestamptz，统一 UTC；revision 整数从 1 起。业务编码规范化后保存，数据库唯一约束包括停用记录，不用“仅启用唯一”的索引。
- 普通主表保留 code/name/status/remark/created_at/created_by/updated_at/updated_by/revision。不强迫从表复制全部字段。
- 草稿始终需要 code/name、归属及结构必需字段；其他“启用必填”字段数据库允许 NULL。API 保存草稿校验所有已填字段及关联合法性，启用时执行完整必填。UI 明确两种校验时点。
- 数字列：换算 factor NUMERIC(20,6)，CHECK(factor > 0)；单位小数位 INTEGER CHECK 0～6。入参限制绝对值及小数位以匹配数据库，不由数据库静默舍入。
- 外键原则 ON DELETE RESTRICT；只有未引用草稿的自有明细可以在同事务显式清理。删除已启用/停用记录一律拒绝。审计记录永久保留目标 id 和快照，不对可删除目标建强外键。
- 为跨组织引用增加 company_id/factory_id 及匹配的复合外键，不能只靠客户端传参。表上为被引用复合键建立 UNIQUE。唯一性、外键作为最后防线，服务层返回易懂错误。
- 状态改变、子表修改、修订号增加和审计写入在同一事务。UPDATE ... WHERE id=? AND revision=?，影响 0 行返回冲突；不要先读后无条件覆盖。

### 4.2 S1 表清单

字段长度、枚举和必填业务含义沿用主数据详细设计；本表补充物理关系。没有列出的设计字段不得因省略而丢失，例如 address、contact_name、phone、remark 均应映射。

| 表 | 核心列/关系 | 数据库约束及索引 |
| --- | --- | --- |
| companies | 通用列、address | UNIQUE(code) |
| factories | company_id、address | FK company；UNIQUE(company_id,code)、UNIQUE(id,company_id) |
| warehouses | company_id、factory_id、location_type、custodian_supplier_id、address | 复合 FK factory；供方与公司匹配；UNIQUE(factory_id,code)、UNIQUE(id,company_id,factory_id)；INTERNAL 供方为空，SUPPLIER 非空 |
| locations | company_id、factory_id、warehouse_id、usage_hint | 复合 FK warehouse；UNIQUE(warehouse_id,code) |
| partners | company_id、联系字段、供应能力集合 | UNIQUE(company_id,code)、UNIQUE(id,company_id) |
| partner_roles | partner_id、role、status | PK(partner_id,role)，role 限 CUSTOMER/SUPPLIER，status 限 ACTIVE/INACTIVE |
| units | dimension、decimal_places | UNIQUE(code)，维度枚举 CHECK |
| material_categories | company_id、parent_id | UNIQUE(company_id,code)、UNIQUE(id,company_id)；同公司父级复合 FK；服务层检查全路径循环 |
| materials | company_id、category_id、material_kind、specification、base_unit_id、tracking_mode、serial_uniqueness | UNIQUE(company_id,code)、UNIQUE(id,company_id)；类别同公司 FK；单位 FK |
| material_units | material_id、unit_id、factor | PK(material_id,unit_id)；禁止等于基本单位由服务层检查 |
| material_factory_policies | company_id、material_id、factory_id、allowed_supply_modes、default_supply_mode、allowed_production_strategies、default_production_strategy、preferred_supplier_id、status | UNIQUE(material_id,factory_id)；物料、工厂、供方同公司复合 FK；默认值属于允许集合；完整检查见下文 |
| material_inspection_policies | policy_id、inspection_type、requirement、exemption_reason | PK(policy_id,inspection_type)，仅 IQC/FQC/OQC；豁免原因条件 CHECK |
| users | id、username、password_hash、role、active | UNIQUE(username)；角色 ADMIN/EDITOR/VIEWER/RELEASER |
| user_company_scopes | user_id、company_id | 复合 PK；普通用户显式授权公司 |
| user_factory_scopes | user_id、factory_id | 复合 PK；细分工厂范围，无匹配不授予工厂访问 |
| sessions | token_hash、user_id、expires_at | token_hash 唯一，索引 expires_at |
| audit_logs | id、actor_id、action、entity_type、entity_id、company_id、factory_id、before_json、after_json、reason、occurred_at | 索引(entity_type,entity_id,occurred_at)及组织范围；不记录密码或会话令牌 |
| schema_migrations | version、checksum、applied_at | version 主键；已应用迁移不可改写 |

供应能力及允许方式可用 PostgreSQL text[] 存有限枚举集合，CHECK 集合非空/元素合法及默认项包含关系；不使用无约束逗号字符串。生产策略在 MAKE/SUBCONTRACT 时非空且有默认值，只 BUY 时允许空。供应商角色与能力有效性仍在事务内查询校验。物料策略按物料聚合保存；修改其状态或明细也增加物料 revision，避免多个页面覆盖。

首批不建空的 BOM/路线表，default_bom_code/default_route_code 随 S2 增加外键迁移，S1 UI 不给无法解析的自由文本输入。此为实施分片，不删除业务设计字段。工厂策略启用不强制已有 BOM/路线；后续生产方案发布/下达时执行版本依赖校验。

### 4.3 必须实现的关联与生命周期约束

1. 归属公司自创建后不可随意转移；子资料继承归属，客户端提交的冗余 company_id 必须与父对象一致。普通用户不能靠篡改 id 获取其他公司的详情、引用或审计。
2. 新增引用要求目标及上级有效。既有草稿/详情可显示此前已选但后来停用的资料，以禁用选项标识；启用或新增引用时拒绝。停用上级不批量改写子级状态，但 `effective_active` 计算含所有祖先。
3. 分类更新 parent_id 前遍历祖先并在事务内串行保护同公司分类结构（可用事务级 advisory lock），避免并发两次更新造成环。
4. 仓库建草稿时可同时建 DEFAULT 草稿库位。启用仓库操作在单事务中校验公司、工厂、供方，并启用 DEFAULT（或用户指定的首个库位）及仓库，解决“仓库须有启用库位、库位须有启用仓库”的初始化循环。以后不能停用最后一个有效库位而留下启用仓库；允许先停用仓库再处理库位。
5. 供应商处仓库只表示位置和保管方；UI 没有把它设为“不属于我方”的物权开关。质量不是仓库状态，S1 不提供库存余额或质量放行。
6. 往来单位角色可多选，角色单独停用；已经被仓库或供方策略引用的供应商角色不能删除，只能停用并提示影响。单位角色、整体状态、上级组织共同决定是否可用。
7. 物料默认供应方式属于允许方式；生产策略是独立字段。序列管理要求件类且零小数基本单位。换算仅适用于当前物料，零/负/超过六位小数拒绝。
8. 有引用的单位精度、物料基本单位/追踪模式禁止直接变更；首批已有工厂策略/辅助单位等结构引用时也禁止破坏性改写，必要调整须明确清理未发布配置或使用新的物料。启用后编码固定；所有状态变更须原因并审计。
9. 引用统计只返回实际已实现关系。未建设订单模块时，界面显示“业务订单引用尚未接入”，不能伪造未完订单数为已核对的 0。

## 5. API 合约与权限

### 5.1 REST 合约

前缀 /api/v1；资源使用 companies、factories、warehouses、locations、partners、units、material-categories、materials。

| 方法/路径 | 用途 | 约束 |
| --- | --- | --- |
| GET /resources | 搜索、分页、组织/状态筛选 | page>=1，pageSize 默认20、最大100；排序白名单；返回 items,total,page,pageSize |
| GET /resources/:id | 详情及自有明细 | 权限校验后返回；含 revision 和有效性原因 |
| POST /resources | 新建草稿 | 不接受客户端审计字段；返回 201 |
| PUT /resources/:id | 保存允许修改字段及自有明细 | body 包含 revision；白名单字段；事务保存 |
| POST /resources/:id/activate | 启用 | revision、reason，执行完整校验 |
| POST /resources/:id/deactivate | 停用 | revision、reason，保留历史引用 |
| DELETE /resources/:id | 删除未引用草稿 | revision；引用或状态不符返回 409 |
| GET /resources/:id/references | 引用明细与影响 | 限用户可见范围，不能泄露其他组织数据 |
| GET /resources/:id/audit | 审计历史 | 不返回敏感认证字段 |
| POST /materials/:id/convert | 单位换算验证/预览 | quantity 为字符串、fromUnitId；校验源单位精度，返回基本单位字符串 |

resources 为文档占位，不是任意表名接口。material 明细包含 unitConversions、factoryPolicies、inspectionPolicies；partner 明细含 roles、supplierCapabilities。列表有 activeOnly 可选，供选择器使用；普通维护列表默认包括草稿、启用、停用。

统一错误 `{error:{code,message,fieldErrors?,requestId}}`：400 请求格式错误；401 未登录；403 操作无权限；404 不存在或不可见；409 编码冲突/引用冲突/并发冲突；422 业务校验不通过。错误信息中文；服务器 SQL 栈不暴露给前端。成功详情 `{data:...}`，列表分页结构固定。NUMERIC 通过字符串 JSON 传输，不自动转为 Number。

### 5.2 最小身份与授权

- 认证接口：POST /auth/login、POST /auth/logout、GET /auth/me。用户管理接口：GET/POST /users、PUT /users/:id（角色、启停用、组织授权），仅 ADMIN 可用；重置密码使用独立操作，不在普通详情返回哈希。初始化命令处理第一个管理员，后续账号可通过页面维护。
- 使用用户名密码登录，Node crypto.scrypt 带随机 salt 哈希；会话为随机高熵令牌，数据库存令牌哈希，cookie HttpOnly、SameSite=Lax，生产 HTTPS 时 Secure。默认 8 小时到期，登出删除会话。
- 同源写请求检查 Origin（开发仅允许明确配置地址），JSON 接口拒绝非预期 Content-Type；登录限流，密码错误使用统一提示。
- ADMIN 管理全部组织、单位及用户；EDITOR 可查看/保存授权组织资料但不启停用；RELEASER 可查看并启停用授权资料；VIEWER 只读。初版角色固定、用户可选择角色，不建设角色编排引擎。
- 普通用户只访问 user_company_scopes 的公司资料，工厂级资料还需 user_factory_scopes 匹配。全局单位所有已登录用户可读，仅 ADMIN 可维护；公司创建和用户授权仅 ADMIN。
- S1 提供管理员用户列表、建立/停用账号、角色及公司/工厂授权的基础页面或等效受保护界面；禁止通过任意 X-User-Id 头充当用户。
- 初始化管理员通过本地命令及明确设置的密码创建，不把真实密码写入 Git/文档。演示账号只在显式 demo 初始化时建立；README 写明初始化方式。不可用公开固定管理员密码当生产默认。

## 6. 中文界面与操作体验

左侧导航：组织与仓储（公司、工厂、仓库、库位）、往来单位（客户、供应商，共享同一资料，允许切换全部）、物料基础（单位、分类、物料）、系统（用户权限）。顶部显示当前用户与退出；组织过滤为筛选而不是安全边界。

每页必须有可用的搜索、状态/组织筛选、分页、新建、编辑、详情、启用/停用、删除草稿操作；不允许用纯 JSON 编辑器代替物料表单。详情显示关联编码/名称、有效性、引用及审计；操作按钮按权限与状态隐藏/禁用，后端再校验。

物料表单分页签：基本资料、辅助单位、工厂策略与检验要求。供应方式和生产策略分别多选，默认值选项只取已选集合。角色采用多选，供应商能力随角色显示。供应商仓必须选择同公司有效供应商。分类可用树形选择，禁止选自身或子孙。

草稿保存缺失项与启用失败提示分开；422 定位到表单字段，409 并发冲突提示重新加载，不能自动覆盖。删除/停用呈现影响并收集原因。空状态、加载、失败重试均有中文说明。桌面 1280px 可用，较窄屏表格横向滚动，不能让关键操作不可见。

## 7. 迁移、初始化与运行方式

实施代理提供以下命令（命名可微调，README 必须一致）：

1. `npm install`，生成锁文件；`docker compose up -d db` 启动项目专属 PostgreSQL。
2. `npm run db:migrate` 按序执行 SQL 迁移并核验 checksum；每个迁移事务执行，失败回滚。外键、索引与 CHECK 随迁移建立。
3. `npm run user:create-admin` 交互或环境变量创建管理员；不回显密码。
4. `npm run db:seed:demo` 显式装入示例 C01/F01、CU01/SU01～SU03、WH01～WH03、单位分类和 R01/R02/H01/H02/P01，以及物料策略；可重复执行且不得覆盖用户修改或删除已有数据。
5. `npm run dev` 启动 API 与前端；`npm run build` 构建；`npm start` 运行构建结果；`npm test` 与 `npm run test:e2e` 分别验证。
