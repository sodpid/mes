## 1. 可交付范围与当前业务尚未存在的处理

新增一级“编号中心”，二级“编号规则”“分配记录”；不要挂在仅ADMIN可见的现“系统”组内而隐藏其他有权角色。规则CRUD、启停、预览和记录只读查询是真实功能。页面提示“生产订单、建批、单件追溯尚未接入；分配记录由业务事务产生”。生产初始无分配记录属正常空状态。

实际取号只提供内部`allocateNumbers(tx, actor, request)`，由未来业务服务在同一个Connection事务中调用，不自行BEGIN/COMMIT，不开放HTTP allocate/reserve接口，不放“生成订单/批次/孤立号码”按钮。隔离测试使用测试业务表模拟业务保存，证明原子性及回滚；测试表不进生产迁移。不能以独立预留号码代替同事务约定。

MO（生产订单号）、LOT（内部批号）、SN（内部单件号）为本期固定用途。供应商批号、物料编码、GTIN不是本服务自动重编范围；不实现条码图片/打印，不宣称GS1合规。未来同件重打标签读取已有SN，禁止重新取号；建批事件由业务模块定义，不由打印或跨日触发。

## 2. 唯一空间与有限格式

最终号码唯一范围固定为`company_id + purpose + number`，与规则ID无关，规则停用、改名、删除草稿或新建替代规则都不能绕过这个约束。跨公司字符串可以重复；扫码时须携带公司和用途或其他明确业务上下文，不宣称裸号码全球唯一。

内部自动生成SN采用公司+用途内唯一，比现公司+物料的外部SN接受策略更强；这不改变物料`serial_uniqueness=MATERIAL`的既有含义。不提供“扫描裸SN自动跨公司搜索”。

规则支持COMPANY、FACTORY两种作用范围：每条规则固定公司；FACTORY必须固定一个同公司工厂，COMPANY的factory_id为空。不做一条规则任意套所有工厂。scope_key由服务生成非空`C`或`F:<factory UUID>`，不使用可修改名称/编码，不接受客户端scope_key。

格式固定为`prefix + '-' + [dateText + '-'] + paddedSequence`，prefix必填1～24位大写字母数字/下划线，date_format限NONE/YYYY/YYYYMM/YYYYMMDD，sequence_width限3～10，reset_period限NONE/YEAR/MONTH/DAY。reset=DAY要求日期YYYYMMDD；MONTH要求YYYYMM或YYYYMMDD；YEAR要求包含四位年；NONE允许任何日期格式但流水不重置。限制最大最终长度64。例MO_C01_F01-20261024-00001；prefix由管理员明确选择，推荐含稳定公司工厂代号，本批不建设任意模板/SQL/脚本解释器。

计数器使用稳定键`company_id,purpose,scope_key,reset_period,period_key`，**不以rule_id作为唯一计数空间**。同范围同周期的替代规则继续旧流水，避免新建规则悄悄从1重来。period_key：NONE固定`ALL`，YEAR四位年，MONTH六位年月，DAY八位日期。规则改成另一周期/范围时产生另一计数空间，但最终号码唯一约束仍跨规则兜底，碰撞返回409，不循环跳号掩盖配置错误。

同`company+purpose+scope_key`同一时点只允许一个ACTIVE规则，切换时显式停旧启新；按此命名空间加短命名锁或等效锁行，避免并发双启用。旧规则不可重新启用来倒退计数。规则首次启用后核心字段永久固定（purpose、scope、factory、prefix、date_format、sequence_width、reset_period、timezone），仅名称说明可改；变格式需新建规则，状态切换和原因审计。日期规则来自配置，不靠修改业务对象日期触发重新编号。

## 3. 日期、数量和使用约束

FACTORY规则启用时从工厂timezone复制并冻结在规则中；COMPANY规则草稿显式选择IANA时区，建议默认Asia/Shanghai但须表单可见。后续组织时区修改不重写已发布规则时区；界面展示快照及来源。编号日期在业务请求开始时由服务器时间按规则时区计算，重试整个事务保持同一服务器请求时间；客户端不能提供任意过去日期/period_key/startingNumber。

同幂等请求已提交后，无论跨日、规则后来停用或父级后来停用，只要当前调用者仍可见该公司/工厂，返回原结果；不再占号。不允许越权者通过猜幂等键获取结果。

quantity为整数1～1000；MO/LOT只允许1，SN允许批量。流水从1起，单次先检查`current_value + quantity <= 10^width-1`，超限整批422并显示上限，禁止截位、回绕或隐式加宽。计数最大10位，在JS安全整数内；数据库BIGINT读取建议仍统一按字符串处理，计算用BigInt，JSON输出字符串，不使用浮点。

提交成功或已对外输出的号码永久保留、不可删除复用；本期分配记录没有作废/回收HTTP入口，未来业务作废保留原映射。失败事务未提交且从未对外返回的数字可以由下一成功事务使用，这不等于回收已发号码。号码不保证无缺号，不能靠TTL回收已发号。

business_type为内部白名单标识（如production-order、production-batch、product-serial-batch），business_id为预先分配的技术UUID。它代表本次业务对象/批量建件任务，不是自由填写的外部描述；由于相应实体未实现，此列暂不建假FK，接入服务承担对象保存与分配在同事务的责任。SN批量返回ordinal→号码，业务服务逐件保存映射；同一business_id的重试不可新增另一批。实体后续追加SN需一个明确的新建件任务ID，不假装同一请求可以改变数量。

rule_snapshot只存格式、规则ID/revision、作用范围和时区等必要配置；不存完整业务payload或认证信息。fingerprint为服务器规范化白名单请求的SHA256：包括rule_id、purpose、company/factory、business_type/id、quantity及调用业务服务传入的已规范化业务内容摘要；不包含幂等key、当前时间或动态生成的号码。参数变更返回409，原始秘密payload不落日志/审计。

明细归一化存号码，不把号码数组仅藏在JSON里，数据库能直接保证唯一。激活后规则不删除；未曾启用且无任何引用的草稿可删。已生成的计数器/分配/明细没有删除入口。公司、工厂引用统计纳入这四类关系中的业务头/规则，删除保护检查完整引用；界面计数只显示授权范围。

## 5. 分配算法与幂等事务

调用示意：`transaction(tx => { allocateNumbers(tx, actor, request); saveBusiness(tx, result); })`。取号返回只供事务内使用，HTTP响应、消息发送、打印发生在COMMIT后；不能在事务内先打印再保存。未来外部通知使用提交后可靠事件机制，本批不建消息系统。

固定流程：

1. 校验内部请求、actor作用域和对应业务操作权限。先按company+purpose+request_key读取已有分配；同fingerprint返回原明细，变参409；同business_type/id已占号但不同key也409（错误中可指示已存在，不另分配）。
2. 未命中时按父公司→工厂（有值）→规则顺序取得FOR SHARE读锁（规则修改/启停仍取得FOR UPDATE写锁）；核对scope、purpose和有效状态，再次检查幂等记录/对象占号。共享锁允许同公司不同规则并行，又阻止父级停用穿过本事务；不要给每次取号加公司级排他锁。对不同rule并发共享request_key的情况仍由allocation唯一键兜底；若发生唯一竞争，回滚整个外层事务后重新读已有结果并比对，不能继续使用失败事务中的临时号码。
3. 以无副作用upsert建立不存在的计数器行，再按完整唯一键SELECT FOR UPDATE；首次两个请求并发建立同样安全。计算period、检查整批溢出、更新current_value并写allocation与items；审计仅必要摘要，同事务提交。规则与计数器锁只针对当前组织/规则，不用全系统一个大锁。批量一次更新计数器，避免1000次来回锁定。
4. 服务自身不重试局部取号，也不COMMIT。外层业务事务负责对死锁/锁超时进行有限整事务重试（建议最多3次、小抖动，始终同request_key/fingerprint/服务器请求时间）；业务422、格式碰撞和变参409不重试。提交结果未知时重查同幂等key，而非换key重新申请。

namespace激活锁采用稳定公司+purpose+scopeKey，不拿全局大锁。若一个业务事务需调用多个规则，调用方须按company/factory/rule id固定顺序调用，避免反向锁序。第一版允许单次业务事务一个编号用途，跨用途组合留未来业务设计，不要求通用跨规则批量API。

没有公开allocate/reserve/recycle/重置计数接口。页面规则列表、编辑表单、格式样例、当前状态与启停原因；用途用中文“生产订单/内部批次/产品SN”。分配列表与详情可用、空状态解释接入情况，无假订单链接。预览顺序号为样例，不显示为承诺的下一个号。固定格式适合内部字母数字编号，不宣称已符合GS1/零售条码。

ADMIN全权；EDITOR维护草稿/名称说明/删未引用草稿；RELEASER启停；VIEWER只读规则/分配。COMPANY规则和记录需公司权限，FACTORY需公司+工厂权限；公司范围授权本身意味着可看公司级编号记录，不返回超范围工厂记录。所有角色可预览有权范围格式（只读运算）。用户权限仍在现系统菜单；不因可以维护规则自动拥有未来创建生产订单的权限。内部allocator要求调用者拥有业务入口授予的操作授权，不能单凭rule EDITOR就取号。

父级停用：历史配置与分配可查；禁新建/编辑/启用及新分配，允许停用规则和删未引用草稿。已提交幂等重读先验数据范围后返回原结果。父级重新启用不重置计数。改格式必须新规则，同空间先停旧启新；变更说明明确可能接续旧流水。

400格式、401未登录、403角色、404对象不可见、409revision/幂等变参/业务对象重复/号码碰撞/空间双启用、422日期格式周期不匹配/溢出/父级无效。UI409保留输入并允许刷新比对，不自动覆盖；新增或修改异常必须中文可操作，不能回显SQL。
