## 1. 认证与检查可信边界

使用本地 prod.txt 所指定的现有私钥及固定主机密钥文件，以 OpenSSH BatchMode、StrictHostKeyChecking=yes 登录成功。没有临时接受未知主机密钥，也没有修改 known_hosts。仅记录固定文件匹配成功，不额外声称已通过独立渠道验证服务器身份。

本报告不包含用户名、密钥路径、密钥内容、密码或令牌。网络测试仅为 HTTP HEAD；资源用量是本次瞬时快照，不是历史峰值或负载测试结果。

## 3. 端口、网关与网络

- 80/443 已由宿主 Nginx 使用，22 为 SSH；127.0.0.1:3001 已由现有业务使用。MES 不能抢占 3001，也不能覆盖现有网站配置。
- 当前 Nginx 已有域名 sxw.xiaomtech.cn 的 HTTP/HTTPS 配置和证书，并代理现有 localhost:3001。该域名属于已有业务，不能默认作为 MES 入口。
- 本机 HTTPS 探测返回 302，说明 TLS 监听工作；本次探测关闭了证书校验且未验证外部访问，**不证明 MES 域名、证书信任链、DNS或安全组已经就绪**。
- registry.npmjs.org HEAD 返回 200；public.ecr.aws/v2/ 返回正常认证挑战 401；registry-1.docker.io/v2/ 在 12 秒内超时。
- 建议优先使用可达的官方 ECR 镜像来源，或在构建环境准备可导入的镜像。仅验证 registry 端点可达，未证明所有镜像 manifest/层或包下载均可完成。

## 4. 最低可试运行条件与建议容量

现有机器可以作为受控试运行目标：在其他业务平稳时新增一个轻量 Node 服务和独立 PostgreSQL，先限制访问范围、连接数及进程内存，并监测实际峰值。建议初始预算以应用约 256 MiB、PG 约 256～384 MiB 为估算起点，保留宿主和原业务增长空间；这些值**不是已验证的资源需求或上线保证**，过低硬限制同样会导致 OOM，需要通过实际压测调整。

试运行前在其他构建环境完成前后端构建及测试，服务器只加载运行产物；不要在这台低内存共享机执行 Playwright、npm 构建或大批量数据处理。

面向正式多人使用，建议至少提供 2 核、4 GiB 的专属或有明确余量的环境；若继续共享 MySQL 和现有 API，应按所有业务峰值核算，必要时更高。4 GiB 为起步建议，不是完整 MES 的容量认证。添加 swap 可缓冲部分峰值，但不能代替内存容量，也未获本次修改授权。

## 5. 当前项目实际生产缺口

1. **缺应用部署容器配置。** 当前 compose.yaml 只运行数据库，项目未提供应用 Dockerfile、应用 Compose 服务或宿主服务单元。数据库本地配置没有 restart 策略。需要形成项目专属生产 Compose、持久卷、资源边界及重启策略。
2. **应用监听需适配容器。** server.ts 写死 127.0.0.1；若放入普通 bridge 容器，宿主映射端口无法访问容器 loopback。需提供可配置 HOST，在容器内监听 0.0.0.0，宿主只映射到独立 loopback 端口；这不等于把 API 直接暴露公网。
3. **HTTPS 与来源需配套。** 应为 MES 使用独立域名/虚拟主机或经评估的专属入口；WEB_ORIGIN 设置为实际 HTTPS origin，NODE_ENV=production 启用 Secure Cookie。当前 UI 使用相对 /api/v1，推荐同源反向代理，减少额外跨域配置。不能直接套用本地 18080 或已有业务 3001。
4. **迁移需要部署步骤。** 当前 npm run db:migrate 依赖 tsx（开发依赖）；仅安装 production dependencies 的运行镜像不能直接执行该命令。需单独迁移任务/工具镜像或编译后的迁移入口，先校验和备份再执行，失败保留原运行版本。不要在每次普通重启时自动重复初始化管理员或样例。
5. **备份与恢复未落实。** 当前只有 PG 数据卷，没有仓库中的生产定时备份、异机保留或恢复验证。独立数据库用户/口令和卷应由部署配置管理，不导入本地演示数据或复用已有业务 MySQL。
6. **应用健康与运维证据不足。** 数据库已有 pg_isready 健康检查；应用无专用健康接口，Fastify logger:false。需最小应用健康检查、脱敏请求/错误日志及轮转、容器退出/资源异常监测，避免进程存活但数据库不可用时误报健康。

上述是已观察到的部署差距，不改变既定模块化单体+PostgreSQL 架构，也不要求先开发完整采购生产销售功能才能部署 S1 试用。

## 6. 推荐后续步骤（本次未执行）

1. 确定这是试运行还是正式业务使用；为 MES 分配独立域名/入口和资源预算，确认是否升级共享机器内存。
2. 在本地完成生产部署配置与小幅运行适配：应用镜像、HOST、健康检查、日志、迁移任务、备份说明及独立 Compose；保持已有业务不变。
3. 先验证目标镜像来源与构建产物，准备回滚版本。部署前再次检查实际端口、内存及磁盘，不能把本次空闲状态永久视为预留。
4. 获得部署授权后，创建 MES 独立服务与数据库，接入 HTTPS，完成登录/持久化/重启/备份恢复验证，并观察与原业务同时运行时的资源峰值。

本次只完成环境评估。现有 S1 可作为试运行内容；BOM、工艺、检验标准及订单业务仍按 S2～S4 实施，不能称为完整 MES 已具备生产上线条件。
