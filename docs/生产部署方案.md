## 2. 本地构建和应用适配

1. 本地构建Linux amd64镜像，Node24运行已编译API和web/dist；生产依赖在Linux构建阶段安装，不复制Windows node_modules。镜像只包含必要运行产物、SQL迁移及明确的迁移工具；排除.env、prod.txt、私钥、备份、artifacts、测试账号资料。使用.dockerignore白名单式控制，检查最终镜像内容。
2. server.ts当前写死127.0.0.1，改为可配置HOST，默认保持本地值；生产容器HOST=0.0.0.0，容器端口3001，宿主仅映射127.0.0.1:18082。API_PORT按容器端口设置，不能照搬本地18080。
3. 配置NODE_ENV=production、WEB_ORIGIN=https://mes.xiaomtech.cn，保留Secure/HttpOnly/SameSite cookie。同源静态页面与/api/v1不需新增CORS。现有来源白名单支持WEB_ORIGIN。
4. 容器反代需要正确限流客户端IP：不要无条件trustProxy=true。Nginx覆盖X-Forwarded-For为$remote_addr，应用只信任实际宿主/专属桥接入口，配置受控代理范围；验证普通请求不能伪造客户端IP。若暂保持不信代理，必须明确登录限流会按网关共享IP，不能声称已经按用户IP限流。
5. 当前/api/v1/health位于认证保护下且返回数据库名/版本；新增最小无需登录的健康端点仅返回ok、数据库连通结果（不暴露版本/库名），用于容器healthcheck。保留已有受保护详情健康接口。
6. 打开最小脱敏结构日志，移除cookie/authorization/密码/SQL值；设置日志轮转，restart:unless-stopped、健康检查及约256MiB起步内存边界（依据实际验收调整），Node堆上限低于容器限制。不在服务器运行npm build或Playwright。

上传docker save产物及checksum到/opt/mes/releases/<版本>/，在远端核对再docker load；使用独立镜像tag、Compose项目mes-prod和目录，避免修改其他项目。部署所需工具镜像也尽量本地准备，线上DockerHub直连曾超时；官方ECR与npm可达不代表所有层已验证。

## 3. 数据库与首次导入

1. 使用已有MySQL容器的管理凭据仅在容器内环境/受限stdin执行授权SQL，禁止将密码放shell命令行、工具输出或日志。随机生成mes专用数据库口令，存/opt/mes/shared的权限600文件，应用用专属账号，绝不root运行。
2. mes使用utf8mb4及既定排序规则。应用账号仅授予mes所需DML；迁移/首次导入可使用独立mes迁移账号，权限限mes，完成后停用/妥善封存，不能授予其他库权限。
3. 网络优先创建mes专属bridge，将已有MySQL容器额外接入该网络并设稳定别名mysql；不改变它现有网络、端口或重启。若复用现有网络，须明确跨项目网络依赖并记录，数据库权限仍隔离。额外network connect不改已有数据服务；后续原MySQL容器重建可能丢附加网络，写入运维恢复说明。
4. 本地源使用短暂冻结本项目写入或同连接一致事务快照，导出全部17表、schema_migrations、UUID/UTC微秒/DECIMAL/JSON/哈希；记录快照截止时间。本地服务随后可恢复，说明上线后以生产数据为准，不自动双向同步。
5. 对远端空mes先执行MySQL迁移，再按外键顺序事务导入业务数据。沿用本地核对的规范化全字段摘要；不覆盖已有表记录、不导入测试库、保持FK/CHECK。迁移历史按已执行脚本checksum核对，不能盲覆盖。
6. 比较17表的行数、主键和规范内容摘要、账号哈希及授权；报告不含实际密码/哈希值。现有本地用户可继续使用原账号密码登录生产。有效会话不作为必须跨环境保持的登录体验，独立域名通常需重新登录，不重置密码。
7. 为mes配置单库备份：只导出mes，定时任务使用受限凭据和专属备份目录，不备份/读取其他业务表。设置保留期及磁盘告警，至少验证一次备份可读/恢复到隔离临时库。外部异机备份目标若未提供，明确当前备份仅本机，不能称灾备已完成。

## 4. Nginx与TLS顺序

先备份当前Nginx配置清单、nginx -t结果及sxw响应状态；不读取/输出私钥。

1. 创建/etc/nginx/conf.d/mes.conf，仅server_name mes.xiaomtech.cn，先监听80，/.well-known/acme-challenge/使用独立webroot /var/www/mes-acme。未拿到证书前普通路径可返回503提示部署中，避免通过HTTP开放生产登录。
2. nginx -t通过才reload（不restart），验证原sxw仍返回原302且容器healthy。DNS已指向此机，可用HTTP-01申请仅mes的新证书，不替换sxw证书。
3. 已补查到现成工具/opt/certbot/bin/certbot，现有sxw使用webroot认证；优先复用此工具，使用mes专属webroot申请，不修改sxw续期配置。绝不运行会自动改动已有站点的安装插件。可沿用现有ACME账户；若需要新账户而无用户邮箱，可使用不登记邮箱选项，同时明确未配置证书邮件通知；不得编造用户邮箱。
4. 加入443站点，使用新mes fullchain/privkey路径。HTTP除ACME挑战外301到HTTPS。HTTPS反代http://127.0.0.1:18082，设置Host=$host、X-Real-IP=$remote_addr、X-Forwarded-For=$remote_addr、X-Forwarded-Proto=$scheme，proxy_http_version 1.1；连接超时5s、读写60s，client_max_body_size 1m与API一致。无WebSocket需求不必扩展配置。
5. 配置仅mes证书的自动续期任务，使用webroot；成功续期后先nginx -t再reload，不能重启或重签他人证书。验证续期配置或dry-run可行性，受CA频率限制时报告具体状态。
6. 若签发受外部CA/DNS/网络阻碍，保留HTTP挑战及应用内部部署成果，报告准确阻碍，不能使用sxw证书假装HTTPS成功，也不降级暴露带SecureCookie的HTTP登录。

## 5. 验收与回滚

验收必须包括：镜像版本/校验、应用健康和数据库连通、HTTPS证书SAN/有效期/信任链、HTTP跳HTTPS、同源Origin写请求、登录后SecureCookie、权限隔离抽查、原资料与审计展示、创建测试草稿后删除及重启持久化。使用原账号凭据可安全获取时登录；否则可建立仅用于验收的随机临时账号，验证后删除其会话/授权及账号，恢复17表数据摘要，不能重置现有管理员。

对比部署前后sxw状态/证书及原API/MySQL健康、端口、内存余量。检查实际访问日志无秘密、重启策略及备份可用；报告内存峰值只能引用实测，不声称已完成容量压测。

回滚：新站点失败则撤销mes.conf并nginx -t/reload，仅停止mes-prod应用；已有MySQL不停止、不重建，保留mes库及备份以免损失新写入。应用版本问题切回上一MES镜像；本次首次上线无旧MES镜像时保留维护提示。已经接受生产新写入后，不用本地快照覆盖数据库。证书文件可保留，不影响原站点。
